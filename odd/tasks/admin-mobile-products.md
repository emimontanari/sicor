# Feature: admin-mobile-products

Mobile-first admin dashboard for products: hamburger navigation, filter side drawer, per-item "…" menu (edit, hide, delete). Deleting archives a product in our database so supplier sync never re-proposes it.
Tracking unit; behavior is delivered and tested in T1–T3.

## Specs

- **S1 — Mobile-first admin.** L1 verbatim: "Bueno, ahora vamos a empezar a trabajar en el dashboard. Quiero que sea un dashboard cómodo de usar en teléfono celular, porque va a ser una persona que va a usar la aplicación 100% en un teléfono celular, entonces el diseño y la comodidad tiene que estar para que la aplicación sea utilizada con un teléfono celular. Entonces los filtros tienen que ver menú hamburguesa, los filtros tienen que estar también como en un menú y que aprietas y que se desplíen para el costado y ahí se pueden activar, en que haya dialogues, que los botones de cerrar estén visibles, que sea cómodo usar administrativamente desde el celular." Admin section navigation behind a hamburger menu; product filters in a side panel (drawer) that slides in from the side, where filters are activated; dialogs with clearly visible close buttons; comfortable one-handed phone use.
- **S2 — Per-item "…" menu.** L2 verbatim: "me equivoque yo funciono, ahora quiero mejorar la UI de los firltros y que haya una opcion para modificar una vez en nuetra base los itemes solo tenemos mostrar que tengo un meno ... que dentro podes editar, ocultar eliminar". Each product row in the admin list has a "…" menu with Editar, Ocultar (Mostrar when hidden) and Eliminar, replacing the current lone show/hide control.
- **S3 — Delete = archive, never re-imported.** L3 (user choice): "Eliminar y no volver a traerlo (Recomendado)" — "Sale del catálogo y de la lista del panel, y las próximas búsquedas de Masefer no lo vuelven a proponer. Queda en una sección «Eliminados» para restaurarlo si te equivocaste." Deleting asks for confirmation in a dialog; the product disappears from the public catalog and from the admin list; supplier sync (append-only, `odd/tasks/append-only-sync.md`) never proposes it again; an «Eliminados» view lists archived products with Restaurar.
- **S4 — Editing stays in our database only.** Edits keep using our stored overrides (name, description, price, show price, category, image, visibility); sync never overwrites them (existing behavior, `odd/tasks/catalog-sync.md` S2).
- **S5 — Bulk at scale, whole filtered list.** L8 verbatim: "Bueno, acá quiero que trabajemos en el sentido de los productos, porque qué pasa? Si yo por esas casualidades quiero mostrar todos los productos, por ejemplo 500, y me los empaginás en de 20 en 20, yo voy a estar tres días habilitando y deshabilitando productos. Entonces quiero que busquemos la manera de que eso sea más fácil de manejar a gran escala los productos. O sea, manejar todos los productos juntos o todos los productos que haya una opción como que sea más cómoda. Porque si no imagínate el celular ir apretando de 25 en 25, mil productos el día de mañana si hay, se vuelve muy tedioso." Bulk operations must scale to the whole filtered list (hundreds of products), not just the current page, and stay comfortable on a phone: a "Seleccionar todos los filtrados (N)" scope sends only the active filter state (the server resolves the codes with the same list matching, never trusting a client code list), updates run in bounded chunks inside ONE transaction (the explicit per-code path keeps its 200 cap), the sheet shows the real scope ("Se aplicará a N productos") and the result reports the exact updated count; plus a 25/100/Todos page-size option so a big screen can also work page-wise. Eliminados keeps no bulk UI.
- **S6 — Reversible reviewed.** L10 (human choice): "si" — to the proposal of NOT adding an extra confirmation to "Marcar como revisados" (the bulk sheet's scope text "Se aplicará a N productos" is the safeguard) and instead making `reviewed` reversible. Per product: the row "…" menu of a reviewed, non-archived, non-discontinued product gains "Volver a Nuevos" (`unreviewAction`: `requireAdmin()` first, then `reviewed=false` plus clearing the visibility decision `visible=null`, revalidates like `reviewAction`), which puts the product back in the "Nuevos para revisar" queue (`isNew` = active + not reviewed + no visibility decision; Eliminados rows keep Restaurar/Editar only). In bulk: "Marcar como nuevo" (`{reviewed: false}`) joins "Marcar como revisados" in the bulk sheet, always available, for both the per-code (200 cap) and scope=all paths; `cleanBulkPatch` validates `reviewed` as boolean, empty-set and eliminados rejections unchanged. Accepted and documented: bulk "Marcar como nuevo" only touches `reviewed`, so a reverted product whose override keeps `visible=true` stays visible and does not re-enter the Nuevos queue (it just stops counting as reviewed); only `reviewed=false` + `visible=null` (the row "Volver a Nuevos" path) is new again.
