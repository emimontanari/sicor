# Feature: append-only-sync

## Specs

- **S1 — Reliable supplier reads.** Allow late supplier results to arrive and retry empty or incomplete reads within a bounded attempt count and overall wait budget. If the budget is exhausted without a usable read, report a failed check and leave the stored catalog intact. Two preview checks returned empty, while a previous read-only smoke returned 552 products (L2); that count is evidence, not a required result or a minimum threshold.
- **S2 — Local catalog and append-only sync.** Preserve the initial import into the app database, the database as the catalog read source, and the current explicit admin confirmation. After the initial import, manual checks and scheduled checks (every 15 days) only submit newly seen supplier codes for confirmation; checks never write to the catalog. Confirming a run inserts only codes still absent from the database. Never update or discontinue an existing code through sync, even if it changes or disappears upstream. Validate only in isolated local Docker with fixture supplier responses and a separate database; no live provider calls, production deployment, or Dokploy credentials.
